# 用語集

| 用語 | 意味 |
|---|---|
| **Hub** | ToolOrchestrationHub。ツールの生死・アラート・リポジトリの状態を 1 か所に集める監視の中継所 |
| **台帳(registry)** | 監視する相手の一覧(`registry.yaml`)。1 件が `ToolEntry` |
| **tool_id** | ツールを指す名前(重複禁止)。`sound_middleware` など |
| **transport** | ツールとのつなぎ方: `http_bridge`・`rpc`・`cli_batch`・`static_site` |
| **category** | Hub がどう関わるか: `monitored`(確認の仕事を持つ)・`observed_only`(受動だけ)・`excluded`(載せるだけ) |
| **死活監視(liveness)** | 「生きているか」の判定。`http_bridge_check`・`rpc_check`・`ci_pipeline_check` |
| **能動(ポーリング)** | Hub から相手に聞きに行く確認 |
| **受動(ハートビート)** | 相手が送る合図の**受信時刻**だけを見る確認。Hub は何も開かない |
| **ハートビート** | 「生きています」という定期の合図(`POST /api/heartbeat/{tool_id}`) |
| **猶予(grace)** | `ci_pipeline_check` で、期待の間隔に掛ける余裕(既定 1.5 倍) |
| **`time.monotonic()`** | 必ず進む時計(時計合わせで戻らない)。経過時間を測るのに使う。値は**そのプロセスの中だけ**で意味を持つ |
| **HealthResult** | 死活監視の結果(`is_up`・`latency_ms`)。不変(`frozen`) |
| **LivenessMonitor** | 受信時刻を保持し、カテゴリごとに能動・受動・スキップを振り分けて判定する |
| **AlertRecord** | アラート 1 件 = 1 回の「発生 → 解消」 |
| **alert_id** | 「同じ異常」を判定するキー。`発生元 : 署名の SHA-256 の先頭 16 文字` |
| **署名(signature)** | 「どの異常か」を表す短い文字列。同じ異常にはいつも同じ値 |
| **dedup(重複排除)** | 同じ `alert_id` の open が既にあれば、新しく作らず 1 件にまとめる |
| **upsert** | あれば更新(または既存を返し)、無ければ追加 |
| **再発** | 解消した後に、同じ `alert_id` が再び起きること。`occurrence_count` が増え、別の `AlertRecord` になる |
| **ingest / resolve** | アラートの取り込み / 解消の記録 |
| **正規化(normalize)** | 送り手ごとに違う形の入力を、同じ `AlertRecord` にそろえること |
| **フラッピング** | 短い時間に open と resolve を繰り返すこと。通知がうるさくなる |
| **スヌーズ** | あるアラートの**通知だけ**を一時的に止める(状態・dedup は変えない) |
| **半開区間** | `[開始, 終了)`。開始の瞬間は含み、終了の瞬間は含まない |
| **状態(ToolState)** | 正常 ✓・警告 ▲・停止 ■・未確認 ○・対象外 –(色だけに頼らず記号と文字を添える) |
| **未確認** | 信号がまだ一度も無く、判定できない状態。偽の「正常」「停止」を出さない |
| **純関数** | 同じ入力に同じ出力を返し、外の状態を読み書きしない関数(`derive_tool_state` など) |
| **Protocol** | 「この形のメソッドを持っていればよい」という約束(構造的な型付け)。継承は要らない |
| **コールバック** | 関数を渡しておき、あとで呼んでもらう(`on_open`・`on_resolve`) |
| **疎結合** | 部品が互いの中身を知らないこと(`AlertAggregator` は通知・保存の実装を知らない) |
| **RAII** | 資源の確保と解放を、スコープに結びつける考え方。Python では `with` 文 |
| **CSRF** | 別のサイトのページが、ブラウザ経由で、利用者の権限で勝手に操作を送る攻撃 |
| **DNS rebinding** | 攻撃者のドメインを `127.0.0.1` に解決させ、同じサイトのふりをして、ローカルのサービスを操作・読み取りする攻撃 |
| **Origin / Host** | ブラウザが付けるヘッダ。ページの出どころ / 接続先の名前。ページのスクリプトは偽れない |
| **fail-closed** | 設定が壊れたとき、**閉じる**(起動しない・拒否する)設計。逆は fail-open |
| **役割(role)** | `viewer` < `operator` < `admin`。順位で比べる |
| **定数時間の比較** | 一致しない位置に関わらず、かかる時間が同じ比較(`hmac.compare_digest`)。タイミング攻撃を防ぐ |
| **監査ログ** | 変更系の操作・拒否・ログインを、時刻・名前・役割・結果で残す記録。本文・キーは残さない |
| **fast-forward** | 履歴が分岐せず、ブランチの先頭を進めるだけの取り込み(`git pull --ff-only`) |
| **ホットリロード** | 再起動せずに、設定ファイルの変更を反映すること |
| **span / counter / event** | 計測の 3 種: 区間の長さ・数値の時系列・出来事 |
| **Chrome Trace Event 形式** | `chrome://tracing`・Perfetto で開ける、計測の JSON 形式 |
| **p50 / p95** | パーセンタイル。中央値 / 「ほとんどの場合の上限」。平均より、遅い瞬間を見やすい |
| **ランブック(runbook)** | アラート種別ごとの運用手順書(やること・やらないこと・成果物) |
| **隔離方式(isolation)** | ツールを動かす方針の記録: `none`・`sandbox-bash`・`container`・`vm`(Hub は隔離しない・台帳に残すだけ) |
